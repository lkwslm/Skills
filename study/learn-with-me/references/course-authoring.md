# 课程写作协议

## 生命周期

使用同一个 `units/NNN-slug.html` 文件经历：

1. `draft`：写目标、前置、问题场景和已确认检查点；不生成五题自测，不链接尚不存在的下一课。
2. `verification`：推导主体完整，加入五题自测及解析，等待学习者选择课堂出口。
3. `completed`：学习者明确确认后定稿，结算概念、路径、计数和导航。

根元素的 `data-lesson-status` 与 `state.yaml` 的当前活动保持一致。完成课程不再作为当前活动。

## 固定章节

按需使用模板中的章节，但保持以下顺序：

1. 学习目标；
2. 前置连接；
3. 问题与场景；
4. 逐层推导；
5. 实例、源码或数据落点；
6. 选择点与替代设计；
7. 理解验证；
8. 结果与反思；
9. 档案更新；
10. 来源索引；
11. 课程导航。

长课程生成页内目录。正文使用学习者的语言，概念 ID、代码标识符和来源 ID 保持稳定。

## 五题自测

- 在 `verification` 阶段一次生成恰好五道选择题。
- 让五题全部作答后统一提交；不设置及格线。
- 为每题收集“确定、犹豫、猜测”信心值。
- 结果展示总分、正确答案、每个选项的解析及关联概念 ID。
- 允许重做；结果只存在页面会话中，不写 `state.yaml`。
- 选项对应真实误解或权衡，避免显而易见的陪衬项。
- 若五题不足以验证推导或应用，在正文另加开放任务；仍保持选择题数量为五。

## 证据与图示

用视觉标记区分事实、作者说明、推断和假设。关键外部事实在本课来源区引用 `sources.md` 的来源 ID。

Mermaid 源码保存在 `concept-map.md` 或课程的折叠区；可用渲染工具时将结果以 inline SVG 嵌入 HTML。不得引用 CDN 或外部 Mermaid 运行时。无法渲染时保留源码并明确标记“待渲染”。

## 导航

- 只链接实际存在的相邻 HTML，使用相对路径。
- 下一课尚未生成时展示标题和目标预告，不创建链接。
- 生成新课时反向更新上一课；同时给新课添加上一课链接。
- 综合回顾到期时将下一步指向回顾 HTML；回顾完成前不链接后续普通单元。

## 页面检查

定稿前确认：HTML、CSS 和 JavaScript 全部内嵌；没有外部资源依赖；移动端可读；键盘可操作；五题数量准确；隐藏解析仅在提交后显示；导航目标存在；页面状态、标题、编号和 `state.yaml` 一致；不存在未替换模板标记。
