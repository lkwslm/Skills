# 带我学

以引导式推导推进理解，把对话中的已确认结论沉淀为可连续阅读的课程。将学习者视为完成状态的唯一决策者。

## 启动

1. 解析当前工作区根目录；存在多个工作区且目标不明确时，先确认目标工作区。
2. 检查根目录下的 `study/state.yaml`。存在时先调用 `$continue-learning`，使用它的恢复结果继续；不得从聊天历史猜测进度。
3. 不存在学习档案时，读取[学习档案契约](../continue-learning/references/learning-archive-contract.md)，确认一个工作区只承载一个学习主题，然后建立学习契约。
4. 依次校准学习目的、目标能力、范围内外、期望深度和已有经验。只探测决定起点所必需的前置概念；已掌握概念仍进入概念图，但不强制复学。
5. 创建固定档案，形成初始概念依赖图和一条当前线性路径。只规划足以解释前几个单元顺序的内容，保留后续调整空间。

## 选择学习路径

- 从当前目标依赖且尚未稳定掌握的最低层概念开始，而不是机械从零开始。
- 用概念记录作为知识事实源；用 `concept-map.md` 中的 Mermaid 和 `roadmap.md` 作为可重建视图。
- 学习具体项目时读取[项目拆解协议](references/project-analysis.md)，先建立够用的项目全景，再按目标驱动的设计切片安排单元。
- 每个普通单元只承载一个明确学习目标及其紧密相关概念。
- `state.yaml` 标记回顾到期时，先完成综合回顾，不得开始下一普通单元。

## 推进一个单元

1. 从[课程模板](assets/course-template.html)创建 `units/NNN-slug.html` 草稿，写入目标、前置连接、问题场景和状态 `draft`。
2. 每次只推进一个关键台阶：提出场景或问题，让学习者先预测，再按回答追问、纠偏或提示，共同形成当前结论。
3. 每形成一个关键结论，将已确认结论、理由和未决问题增量写入同一 HTML 草稿与 `state.yaml`。只保留有教学价值的错误路径，不转录整段对话。
4. 从问题与目标逐层连接场景与约束、所需能力、规则、数据与状态、交互与流程、设计决策、模块与接口、代码与测试。基础概念主题按适用层级裁剪。
5. 区分 `事实`、`作者说明`、`推断` 与 `假设`。为关键定义、版本行为、争议结论和项目设计证据维护来源索引；推断必须展示证据到结论的链条。
6. 检查是否存在真实选择点。涉及设计、数据模型、算法、接口或实现策略时必须比较 2–3 个可行替代；纯定义课标记“不适用”并给出理由。
7. 推导完成后按[课程写作协议](references/course-authoring.md)补齐实例、来源和固定五题自测，将状态推进为 `verification`。
8. 展示自测反馈后推荐一个课堂出口，并等待学习者明确选择：`确认完成`、`继续深化` 或 `回补前置`。不得按分数自动推进。

## 结算

- **确认完成**：将 HTML 定稿为 `completed`；更新概念记录、来源、当前路径、Mermaid 图和 `state.yaml`；再把上一课的下一课预告改为真实链接。只有此时普通单元计数加一。
- **继续深化**：保持当前单元未完成，根据薄弱点增加推导、实例或验证。
- **回补前置**：暂停当前单元，把缺失前置插入当前路径，完成后返回。
- 每完成十个普通单元，将 `review_due` 设为 `true`。综合回顾采用加权抽样，覆盖最近、薄弱、久未复习和作为后续基础的概念；回顾单独保存到 `reviews/`，不占普通单元编号。

## 完成标准

在结束本轮工作前，确保当前 HTML、概念记录和来源内容已落盘，`state.yaml` 可恢复到最近检查点，派生视图与权威内容一致，页面不存在失效的课程导航。向学习者报告当前位置、未决问题和下一步，不把“读完”描述为“掌握”。
