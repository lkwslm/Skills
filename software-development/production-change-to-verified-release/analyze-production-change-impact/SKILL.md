# 分析生产变更影响

## 核心边界

区分修改范围与影响范围；不得因计划只改一个模块而缩小消费者、数据或运维影响，不得实施或批准变更。

## 启动读取

读取已确认的当前行为基线、`DISC/OPEN` 决策、变更意图、代码/运行依赖图、已发布契约、数据/配置和历史故障证据。

## 前置门禁

基线必须当前，重大事实冲突已裁决；目标变更边界可陈述。否则 `blocked`。

## 执行流程

1. 从计划修改点向上游调用方、下游消费者、数据、缓存、队列、任务、配置和运维依赖扩展闭包。
2. 分析权限、安全、隐私、并发、性能、容量和故障传播。
3. 标注受影响、证据支持的不受影响以及未知节点；未知不能归入不受影响。
4. 为每个影响关联回归、契约、迁移、观测和恢复验证。
5. 依据可逆性、数据风险、消费者数量和证据置信度给出风险等级与发布策略建议。

## 写入权限

只写 blast-radius map、影响分类、回归范围、风险和建议门禁；不得改代码、Spec、配置或生产状态。

## 输出与状态

输出直接/间接影响图、明确不受影响证据、未知项、风险等级、验证范围和发布策略。

## 失败、阻塞与陈旧

依赖闭包不完整、高风险消费者未知或数据迁移影响未分析时 `blocked`。基线或变更意图 hash 变化时影响图及下游 `stale`。

## Handoff 与完成证据

向 Delta Spec 作者提供图版本/hash、节点证据、回归选择器、风险理由、未知项和所需审批。
